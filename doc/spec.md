# 韓國首爾旅遊網站 - 系統規格書

## 1. 專案總覽

本文件旨在提供「韓國首爾旅遊網站」的綜合規格，以作為開發和驗收的依據。此網站是一個提供首爾旅遊資訊、行程規劃與社群互動的一站式平台。

### 1.1 目標使用者

-   **一般使用者**: 計畫前往首爾的自由行旅客，需要獲取資訊、規劃行程。
-   **管理員**: 網站內容的維護者，負責確保資訊的正確性與即時性。

## 2. 功能規格

### 2.1 使用者端功能

| 模組 | 功能點 | 詳細描述 |
| :--- | :--- | :--- |
| **使用者帳戶** | 註冊/登入 | 使用者可透過 Email 註冊帳戶，並使用帳號密碼登入。提供忘記密碼功能。 |
| | 個人資料 | 使用者可以編輯自己的暱稱、頭像等基本資料。 |
| **旅遊資訊** | 分類瀏覽 | 資訊以「景點」、「美食」、「購物」等分類呈現。 |
| | 詳細內容 | 每個地點皆提供詳細說明、地址、營業時間、照片及使用者評價。 |
| **搜尋** | 關鍵字搜尋 | 使用者可透過關鍵字尋找地點。 |
| | 進階篩選 | 支援依據區域、類別、評分等條件進行篩選與排序。 |
| **行程規劃** | 建立與管理 | 使用者可以建立、儲存、編輯及刪除多個行程。 |
| | 加入地點 | 可將網站上的任一地點加入指定日期的行程中。 |
| | 視覺化地圖 | 在行程頁面，系統能於地圖上展示所有地點的相對位置。 |
| | 分享 | 使用者可將行程透過連結分享給他人。 |
| **社群互動** | 評論與評分 | 使用者可對地點發表文字評論，並給予 1-5 星的評分。 |

### 2.2 管理後台功能

| 模組 | 功能點 | 詳細描述 |
| :--- | :--- | :--- |
| **管理員帳戶** | 安全登入 | 管理員擁有獨立的登入後台。 |
| **內容管理 (CRUD)** | 地點管理 | 管理員可新增、檢視、修改、刪除所有旅遊地點資訊。 |
| **使用者管理** | 帳戶控制 | 管理員可以查看所有使用者列表，並具備停用或重新啟用特定帳戶的權限。 |

## 3. 技術規格

### 3.1 系統架構

本系統採用前後端分離的現代化架構。

-   **前端 (Client)**:
    -   **技術**: React.js (或同級 SPA 框架)。
    -   **職責**: 負責所有使用者介面的渲染、互動與狀態管理。透過 REST API 與後端進行通訊。

-   **後端 (Backend)**:
    -   **技術**: Java 搭配 Spring Boot 框架。
    -   **職責**: 處理所有核心業務邏輯，包括使用者驗證、資料存取 (CRUD)、API 端點的提供。

-   **資料庫 (Database)**:
    -   **技術**: PostgreSQL (關聯式資料庫)。
    -   **職責**: 永久儲存所有應用程式資料，並確保資料的完整性與一致性。

### 3.2 資料庫綱要 (Database Schema)

| 資料表 | 主要欄位 | 說明 |
| :--- | :--- | :--- |
| **users** | `user_id`, `username`, `email`, `password_hash`, `role` | 儲存使用者及管理員帳戶，`role` 欄位用於權限區分。 |
| **locations** | `location_id`, `name`, `description`, `address`, `category`, `latitude`, `longitude` | 儲存所有旅遊地點的詳細資訊。 |
| **itineraries** | `itinerary_id`, `user_id`, `name` | 儲存使用者建立的行程基本資料。 |
| **itinerary_items** | `item_id`, `itinerary_id`, `location_id`, `item_order` | 建立行程與地點之間的關聯，並定義地點在行程中的順序。 |

## 4. 非功能性需求

-   **效能 (Performance)**: 核心頁面載入時間應在 3 秒內，伺服器平均回應時間應低於 500ms。
-   **使用性 (Usability)**: 網站需採響應式設計 (RWD)，確保在桌面與行動裝置上均有良好體驗。介面應直觀易用。
-   **安全性 (Security)**: 使用者密碼需加密儲存，所有資料傳輸均使用 HTTPS。需防禦 XSS、SQL Injection 等常見攻擊。
-   **可靠性 (Reliability)**: 系統上線時間 (Uptime) 應達到 99.5%。
